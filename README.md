## 一、系统简介

基于 Web 的本地化文本润色工具，通过调用本地 Ollama 大模型 API，实现"文本输入 → 智能清洗 → 风格润色"一站式处理。所有数据处理均在本地完成，不依赖外网，保障隐私安全。

## 二、环境要求

| 依赖 | 说明 |
|------|------|
| Python 3.x | 用于启动本地 HTTP 服务器 |
| Ollama | 本地大模型运行环境（[安装地址](https://ollama.com)） |
| 已安装的模型 | 如 `llama3`、`qwen2` 等（运行 `ollama pull <模型名>` 拉取） |
| 浏览器 | Chrome / Edge（推荐） |

## 三、快速启动

1. 启动 Ollama 服务：`ollama serve`（或 Ollama 桌面端自动启动）
2. 首次使用需拉取模型：`ollama pull llama3`（也可拉取其他模型如 `qwen2`、`gemma`）
3. 双击运行 `start.bat`（默认端口 12580，自定义端口：`start.bat 8080`）
4. 浏览器自动打开 `http://localhost:12580`（如未自动打开，手动在浏览器输入该地址）

> 关闭命令行窗口即停止服务。

### 注意事项

- **首次调用较慢**：模型首次加载需 10-30 秒，属正常现象，后续调用会快很多
- **端口被占用**：脚本会自动检测 12580 端口占用，给出友好提示。可改用自定义端口运行：`start.bat 8080`
- **Ollama 未启动**：如果润色无响应，先确认 Ollama 服务已启动（浏览器访问 `http://localhost:11434`，显示 `Ollama is running` 即正常）
- **模型列表为空**：点击"刷新模型"按钮，如果仍为空说明未拉取模型，运行 `ollama pull <模型名>`

## 四、功能说明

### 4.1 模型配置

| 功能 | 说明 |
|------|------|
| API 地址 | 默认 `http://localhost:11434`，支持自定义 |
| 模型选择 | 点击"刷新模型"自动检测已安装的模型 |
| 测试连接 | 验证 Ollama 服务是否可用 |
| 启用 Ollama | 开关控制是否使用大模型（关闭则用本地算法） |
| 思考模式 | 开启后 AI 先分析再输出（更准但较慢），关闭则直接输出 |

**配置持久化：** API 地址、模型选择、开关状态自动保存到浏览器本地存储，刷新页面不丢失。

### 4.2 文本输入与清洗

- 在输入框输入或粘贴文本
- 按 `Enter` 提交，`Shift + Enter` 换行
- 点击"提交并清洗"自动去除口语填充词（嗯、啊、那个、然后等），规范化标点

### 4.3 一键润色（8 种风格）

| 风格 | 说明 |
|------|------|
| 精简摘要 | 提取核心内容，缩短篇幅至原文 30%-50% |
| 正式汇报 | 公文风格，适合向领导汇报 |
| 逻辑重构 | 优化结构，使用逻辑连接词增强连贯性 |
| 语言润色 | 修正语法，优化用词，使表达流畅自然 |
| 口语转书面 | 去除口语填充词，转换为规范书面语 |
| 增强说服力 | 突出观点，使用"问题-方案-收益"结构 |
| 统一风格 | 检测并统一全文的用词、句式、语气 |
| 提升可读性 | 拆分长句，使用标题/列表增强层次感 |

点击风格按钮后按钮高亮显示当前选中状态，润色结果以 Markdown 格式实时流式输出。

### 4.4 流式输出与停止

- **流式渲染：** 润色结果边生成边显示（打字机效果），80ms 节流 + requestAnimationFrame 保证流畅
- **停止生成：** 点击"停止生成"按钮可随时中断，已生成的部分内容会保存
- **Markdown 渲染：** 支持 标题、列表、加粗、代码块等完整 Markdown 语法
- **复制结果：** 复制原始 Markdown 文本到剪贴板

### 4.5 对话上下文

系统自动维护最近 5 轮对话历史（10 条消息），让 AI 能理解上下文实现连续交流。点击"清空"重置历史。

```
d:\tarepj\aivoc\
├── index.html          # 主程序（界面 + 逻辑，纯前端单文件）
├── start.bat           # 一键启动脚本（支持自定义端口：start.bat 8080）

├── .gitignore          # Git 忽略规则
├── docs/
│   └── CHANGELOG.md    # 版本更新记录
└── lib/
    ├── marked.min.js   # Markdown 解析库（本地化，断网可用）
    └── purify.min.js   # XSS 净化库（本地化，断网可用）
```

- **纯前端架构：** 无后端，HTML + CSS + JavaScript 单文件
- **本地依赖：** JS 库已下载到 `lib/` 目录，无需 CDN
- **断网运行：** 只要 Ollama 本地可用，断网也能正常工作
- **XSS 防护：** 所有模型输出经 DOMPurify 净化后才渲染
- **服务器端口：** 默认 12580，可通过 `start.bat <端口号>` 自定义

## 六、常见问题

### Q1：点击润色后没反应

1. 按 `F12` 打开控制台查看错误信息
2. 确认 Ollama 服务已启动（浏览器访问 `http://localhost:11434`）
3. 确认模型已安装（终端运行 `ollama list`）
4. 点击"测试连接"验证 API 可达性

### Q2：输出很慢

1. 关闭"思考模式"（temperature 从 0.7 降到 0.3）
2. 首次调用需加载模型，等待 10-30 秒属正常
3. 使用较小的模型（如 8B 参数量）

### Q3：刷新后配置丢失

检查浏览器是否禁用了 `localStorage`（隐私模式下可能不可用）。

### Q4：复制的内容没有格式

复制功能保存的是原始 Markdown 文本，粘贴到支持 Markdown 的编辑器（如 Typora、VS Code）即可保留格式。

## 七、测试用例

### 用例 1：口语转书面

**输入：**
```
嗯，那个，我觉得吧，这个方案其实还是有很多地方需要改进的。然后呢，就是说我们可能需要重新考虑一下整体的架构。啊，可能我说得不太对，但是确实感觉到有些地方不太顺畅。
```

**操作：** 点击"口语转书面"

**预期：** 去除所有口语填充词，语句规范通顺，保留核心意思。

### 用例 2：正式汇报

**输入：**
```
我们觉得这个项目挺好的，应该可以搞。大家意见都差不多，没啥大问题。可能还需要再完善一下细节，但总体来说问题不大。
```

**操作：** 点击"正式汇报"

**预期：** 转为公文风格，语言严谨客观，结构清晰。

### 用例 3：精简摘要

**输入：**
```
关于这个事情我想说几点。首先就是这个进度的问题，目前来看进度是有点滞后的，主要原因在于前期的需求调研花的时间比预期的要长。然后就是预算方面，目前已经用了大概百分之六十的预算，但是实际完成的工作量只有百分之四十左右，这个比例是有点不太协调的。最后就是下一步的工作安排，我们需要在本月内完成需求的最终确认，然后下周开始进入开发阶段。
```

**操作：** 点击"精简摘要"

**预期：** 长度缩短至原文 30%-50%，保留进度滞后、预算超支、下月确认需求三个要点。
